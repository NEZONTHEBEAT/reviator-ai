# Reviator AI — Frontend

Detect. Decide. Recover.

Frontend only — built to sit in front of your existing FastAPI backend (`app/api/routes.py`, `transaction_router`). No Vite, no bundler: plain HTML, TypeScript compiled with `tsc`, Tailwind compiled with the Tailwind CLI, served with any static file server.

## Stack

| Layer | Tool |
|---|---|
| Structure | HTML |
| Logic | TypeScript (compiled to native ES modules, no bundler) |
| Styling | Tailwind CSS (CLI build) + a handful of hand-written component classes |
| Animation | GSAP + ScrollTrigger (CDN) |
| Utility components | Bootstrap 5 (CDN) — used **only** for the sign-in modal's focus/backdrop handling |
| PDF export | jsPDF (CDN) |
| Dev server | Python's built-in `http.server` |

## Getting started

```bash
npm install
npm run build     # compiles CSS (Tailwind) + TS (tsc) into src/styles/main.css and dist/
npm run serve      # python -m http.server 5500, from the project root
```

Then open **http://localhost:5500**, with the backend running separately (`python -m uvicorn app.main:app --reload`).

While developing, run the watchers in separate terminals (or `npm run dev`, which runs all three via `concurrently`):

```bash
npm run watch:css
npm run watch:ts
npm run serve
```

## Backend contract — confirmed against your `routes.py` / Swagger

Everything lives in `src/config.ts` — if a path ever changes on your side, that's the only file to touch.

```ts
export const ENDPOINTS = {
  health: "/api/health",
  analyseTransaction: "/api/transactions/",
  runAgent: (id) => `/api/transactions/${id}/agent`,
  getTransaction: (id) => `/api/transactions/${id}`,
  executeRecovery: (id) => `/api/transactions/${id}/execute`,
  updateActionStatus: (actionId) => `/api/transactions/recovery-actions/${actionId}/status`,
  getRecoveryActions: (id) => `/api/transactions/${id}/recovery-actions`,
};
```

| Endpoint | Method | Used for |
|---|---|---|
| `/api/health` | GET | Navbar connectivity pill |
| `/api/transactions/` | POST | The form's "Analyse Transaction" — Detect + first-pass Decide |
| `/api/transactions/{id}/agent` | POST | "Run Agent" button — deeper/AI decide pass (not persisted server-side) |
| `/api/transactions/{id}` | GET | "Load" button next to Transaction ID — re-fetch current state |
| `/api/transactions/{id}/execute` | POST | "Execute Recovery" button — Recover |
| `/api/transactions/recovery-actions/{action_id}/status` | PATCH | The status `<select>` on each audit-trail row |
| `/api/transactions/{id}/recovery-actions` | GET | Audit trail list, refreshed after Execute |

Request/response shapes match `app/models/transaction.py` and `app/schemas/recovery_action.py` exactly — see `src/types/api.ts` for the TypeScript mirror.

### One thing to double check: `POST /api/transactions/{id}/agent`

`run_recovery_agent()` (`app/agents/recovery_agent.py`) wasn't shared, so its response shape is unknown. The "Run Agent" panel (`src/components/analysis-result.ts` → `renderGenericObject`) renders **whatever comes back** as a generic label/value list — it won't break, but it also won't have the same polish (badges, icons) as the rest of the result panel. Share that file and I'll wire it up properly.

### Note: `status !== "failed"` transactions are never saved

Per `analyse_transaction()`, a transaction submitted with `status: "success"` returns the "does not require recovery" message **before** `db.add()`/`db.commit()` — it's never persisted. The frontend accounts for this: the result panel shows the "No recovery needed" state and hides Run Agent / Execute (calling either would 404). Don't expect `GET /{id}` to find it afterward — that's the backend's behavior, not a frontend bug.

## Dashboard + Recent Analyses run on local history, not the backend

There's no `GET /api/transactions/` (list-all) endpoint yet, so **Stats** and **Recent Analyses** are computed from `localStorage` (`src/services/history.ts`) — every transaction you analyse/execute/update in *this browser* is recorded there. It's a convenience layer only; nothing sent to your backend depends on it, and it resets if you clear the site's storage or switch browsers/devices.

If you'd rather this backed by the database, add one route to `routes.py`:

```python
@router.get("/")

    return [

            "customer_id": t.customer_id,
            "amount": t.amount,
            "currency": t.currency,
            "status": t.status,
            "recovery_priority": t.recovery_priority,
            "recovery_score": t.recovery_score,
            "recommended_action": t.recommended_action,

```

## Auth (Google + phone OTP)

The navbar's profile icon opens a sign-in modal for both, but **neither `/api/auth/*` route exists on your backend yet** — this was part of the original UI spec, built ahead of the backend for it. It's harmless to leave as-is (nobody has to sign in to use the analyser), safe to hide (remove the profile button in `index.html`'s navbar), or I can help you add matching FastAPI routes if you want it live. Endpoint paths are in `src/config.ts` (`authGoogle`, `otpSend`, `otpVerify`) for whenever that's ready.

Google Sign-In additionally needs a real OAuth **Web** client ID in `GOOGLE_CLIENT_ID` (`src/config.ts`) — until then it shows a small inline note instead of a broken button.

## Design notes

- **Theme** — persisted to `localStorage`, only ever changed by a manual click; refreshing never flips it back. A tiny inline script in `<head>` applies it before first paint (no flash of the wrong mode).
- **Pipeline rail** (Ready → Detected → Decided → Recovered) is driven by real API responses, not a timer — Detected/Decided reveal with a ~300ms stagger since both arrive in the same `POST /api/transactions/` response; Recovered lights up only once `/execute` actually succeeds.
- **Bootstrap** is scoped to the sign-in modal only; everything else is Tailwind.
- Reason codes in the "Failure reason" dropdown are exactly the values `recovery_service.py` / `recovery_decision.py` branch on (`insufficient_balance`, `card_declined`, `network_error`, etc.) — picking anything outside that list still works, it just won't score as well against known logic.
